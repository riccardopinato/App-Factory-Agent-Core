# Factory Read-only Gateway v0.1 — GitHub/AppLab source projection

**Factory baseline:** `App-Factory-Core@c5adc147046beb7024629466d10eeb799c3c2619`, Master v27 / Index v29.

This is the minimum **source-level** foundation for the requested Gateway App Factory. No cloud server, MCP endpoint, Windows deployment, second scheduler, SQLite replica, new LLM or API billing is introduced.

## Current real AppLab seam
AppLab `scripts/durable_store_v54b.py::get_operation(operation_id)` is the canonical persisted operation reader; `scripts/durable_queue_v54e.py` owns queue state. This adapter **does not** clone either component.

`scripts/factory_readonly_gateway.py::FactoryReadOnlyGateway` accepts:
1. `allowed_repositories` from host-controlled auth policy, **not** from an issue, prompt or client payload;
2. a host-injected authenticated GitHub HEAD reader; the host must verify credential scope and source;
3. the real AppLab durable store's `get_operation` method.

Supported (local Python) methods:
- `repository_status(repo, now=...)`: allowlist, exact repo/SHA identity, authenticated source claim and fresh timestamp (<=15 min); returns metadata only. No CI PASS inferred.
- `repositories_status([repos...])`: <=16, reject duplicate/unallowlisted repos before provider calls.
- `operation_status(operation_id, repository, source_sha)`: matches persisted AppLab operation ID, repo and exact source SHA; returns only current state. No payload, token, checkout path, work item or arbitrary SQL.
- `SUCCEEDED` and `DONE` do **not** imply passed CI, physical device verification, release or Golden certification.

Only approved upstream fields flow to the output. Exceptions are fail-closed; no background job, retry daemon, shell, GitHub write, AppLab enqueue or authorization grant exists in this module.

## Host obligations / absent functionality
- An authenticated **runtime host** must connect these read methods to actual ChatGPT/GBrain surfaces with least-privilege permission checks. The present code **does not expose MCP tools** and does not deploy anything.
- The GitHub source callback MUST verify provider authenticity; its `authenticated: true` field is a trust assertion supplied by the host, not cryptographic proof generated by this Python class.
- The AppLab object MUST be canonical and pinned to a trusted checkout, not a client-supplied fake.
- Request logs / sensitive operation data must not be exposed to clients. No independent consumer end-to-end test yet.
- Keep AppLab the sole write authority and replay/lease scheduler; use X10-010/011/012/013 and signed approvals for *any* future write workflow.

## Concrete GitHub connector read seam (source addition)
`scripts/factory_github_connector_reader.py::GitHubConnectorHeadReader` builds the bounded, read-only authenticated **GitHub connector** branch GET from a host-controlled repo→branch map. It consumes the observed `mcp__GitHub__fetch` envelope (`result.content` containing branch JSON) and returns the metadata required by `FactoryReadOnlyGateway`. It never stores or requests a separate PAT. URL host is fixed to `api.github.com`; branch path is URL-encoded and repo allowlisted. The host must still provide the existing connected GitHub fetch action; this Python adapter cannot directly invoke a ChatGPT plugin by itself.

The offline integration test composes `GitHubConnectorHeadReader` with `FactoryReadOnlyGateway` and a fake AppLab store to check identity and output. **Not a live GitHub-to-AppLab MCP deployment.**
